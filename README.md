# derykams.fieldaudit — аудит изменений полей CRM

Черновик модуля для Битрикс24 (коробка). Отслеживает изменение полей
CRM-сущностей: фиксирует старое и новое значение, автора и время.

## Как работает

1. При установке создаётся ORM-таблица `b_derykams_fieldaudit_log`
   (одна запись = одно изменённое поле).
2. Регистрируется D7-обработчик события `crm` → `onCrmDynamicItemUpdate`
   (общее для всех смарт-процессов).
3. Обработчик берёт объект `Bitrix\Crm\Item` прямо из параметров события
   и считает дифф без повторного чтения БД:
   - `isChanged($field)` — поле менялось в этой операции;
   - `remindActual($field)` — старое значение;
   - `get($field)` — новое значение.
4. Дифф пишется в таблицу лога. Ошибки аудита никогда не ломают
   сохранение элемента (все add обёрнуты в try/catch).

## Настройки (UI в админке)

После установки: **Администрирование → Сервисы → Контроль полей CRM**
(`derykams_fieldaudit_settings.php`).

Интерфейс (4 вкладки: UI-анализ / Правила / Симуляция / Конфигурация):

- **Правила** — дерево условий: поле (UF_CRM_* или штатное) + триггер
  («на изменение» / «на заполнение») + действие (запуск БП / окно заполнения
  обязательных полей). Группы с логикой И/ИЛИ вкладываются друг в друга —
  сложные условия от 2 полей.
- **Симуляция** — прогон правил на виртуальных состояниях полей + встроенные
  самотесты логики (в т.ч. кейс «заполнен 1 из 2 — проверка не срабатывает»).
- **Конфигурация** — JSON-экспорт/импорт.

Сохранение: `BX.ajax.runAction('derykams:fieldaudit.api.settings.save')` →
`SettingsController::saveAction` → JSON в b_option (ключ `config_json`,
структура `['rules' => [...]]`). Требуются права W на модуль и sessid.

Каталоги для UI собираются на сервере: UF-поля сделки
(`$USER_FIELD_MANAGER->GetUserFields('CRM_DEAL')`, string/file) и шаблоны БП
(`WorkflowTemplateTable`, документ `crm`/`CRMDEAL`).

## Установка

1. Скопировать папку `derykams.fieldaudit` в `local/modules/` портала.
2. Админка → Marketplace → Установленные решения → установить модуль.
3. Установщик копирует: admin-заглушку в `/bitrix/admin/`,
   JS/CSS в `/bitrix/js/derykams.fieldaudit/`.

## Деинсталляция

При удалении таблица лога и настройки сохраняются (чтобы не потерять
собранный аудит). Ручная очистка:

```php
Bitrix\Main\Application::getInstance()->getConnection()
    ->dropTable(\Derykams\FieldAudit\AuditLogTable::getTableName());
\Derykams\FieldAudit\Options::clear();
```

## Ограничения черновика (что доделать)

- Трекаются только смарт-процессы (`onCrmDynamicItemUpdate`). Для сделок
  D7-событие со старыми значениями в ядре отсутствует — есть только
  совместимые `OnAfterCrmDealUpdate` (приходят лишь новые значения).
  Вариант доработки: в `OnBeforeCrmDealUpdate` кэшировать старые значения
  по ID, в `OnAfterCrmDealUpdate` считать дифф.
- Логи пишутся синхронно. При больших объёмах перенести в очередь/агента.
- Нет UI: ни страницы настроек, ни просмотра лога — только API таблицы.
